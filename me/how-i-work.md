# 我怎么做事

## 别让每个人都从零开始

我做的事里，有个念头一直都在：别让每个人都从零开始。在社团，我想把活动怎么办、组织怎么运转写成文档留下来；做软件，我在意模型好不好懂、大家手里的信息是不是同一份、验证靠不靠得住；有了 AI Agent 以后，我开始想怎么让人和 Agent 一起理解、维护、改进同一个系统。

组织一换人就把前人的经验全扔了，我很不喜欢。社团和实习里都碰到过：知识散得到处都是，术语各说各的，文档跟不上实际情况。我也不止一次自己动手去整理。

## 先搞清问题，再决定加不加复杂度

写代码时，我习惯先搞清楚目标、约束和根因，再找简单、可靠、好维护的办法。一个功能老要打补丁，我宁可回头重新看模型或架构，也不想一直往上叠特例。

## 让软件从 AI 里长出来

我对 Agent 感兴趣，可不是想在软件里加个聊天框。我在琢磨更深一层的协作：代码、文档、业务术语、架构决策和自动化验证，都变成人和 Agent 共用的信息，让 Agent 实实在在地参与系统的建设和维护。

这个方向还在摸索，我拿一句英文概括过：

> Stop putting AI into software.  
> Grow software out of AI.

人和 Agent 共用的这些信息之间是什么关系，我写成过一篇[软件工程的信息模型](https://github.com/shenxianovo/formal-models/blob/main/models/software-engineering-information.md)：代码、需求、测试、日志这些材料各自表达什么，哪些能从已有材料推出来，哪些得靠决策或观测补上，怎样以能接受的成本把它们之间的关系维护住。

## 想到就做，交给 Agent 时再写清楚

我很少提前规划每天干什么，也不用日历或待办清单安排生活，基本想到什么做什么。个人项目也是，做哪个功能常常是想到就做，没有排好的长期计划。

有灵感时，条件允许我一般马上动手。可现在在实习，上班时想到个新功能或项目点子，手上又有急活，只能先记着。下班后通常只想打游戏，所以这些点子多半拖到周末。动不了手的时候，我就在 QQ 上给自己发条消息，把想法扔进去，再标成未读；没做完就一直未读着。我开 QQ 开得很勤，这样总能看到还没做的事，比专门开个笔记或任务软件顺手。

不过写 Orisumi 这类软件时，我会用 ADR、Issue 这些比较规整的流程。这些是给 AI Agent 看的，好让它理解需求、拆任务、执行和验证，跟管我自己的时间没关系。ADR → Issue 这套是跟 Matt Pocock 的 Skill 学的。下一步做什么我可以很随意地定，可一旦要让 Agent 动手，就得用这些材料把事情讲清楚。

## 先上手试，不好玩就放下

对不熟的领域来了兴趣，不管是新技术、VR 还是金融市场，我一般直接上手试，不会先花很久系统学概念和原理。试了觉得没那么好玩，就放下去玩别的，不逼自己。单片机 → C++ / Qt → C# 就是这么过来的。

放下了，学过的东西也还在。原理、上手经验、技术上的直觉，说不定哪天就用上了：单片机让我一眼看穿「ESP32 接 LLM API」的所谓 “AI 硬件”（见 [2023-summer.md](experience/2023-summer.md)），画画和 3D 建模后来也各自派上过用场（见 [life.md](life.md#做东西)）。这些尝试大多很浅，谈不上精通，可亲手碰过一个领域，就算没接着做，我也更明白它的工具和流程，跟懂行的人合作也顺一些。

## 认得出，说不出

要问我日常有什么特别讨厌、受不了的事，肯定有，可让我列出来、讲清楚为什么讨厌，我常常说不上来。有时觉得自己的「输出模块」不太好使。

拿机器学习打个比方：我脑子里好像已经有了某种高维向量似的表示，就是不好翻成文字。碰到让我不舒服的人、行为或东西，输入很容易对上某个内部表示，匹配到「我不喜欢」；反过来，要从这种感觉出发说出一套清楚的描述和理由，就难多了。像一个正着算很容易、反着解很难的函数。很多时候判断早就有了，只是还没找到词。

讨厌的人和事是这样，技术架构、UI 审美、音乐也一样：给我一个具体的方案、界面或声音，我很快就能判断好不好、对不对，可要我马上说出是哪部分、哪条原则让我这么觉得，就很难。与其让我凭空讲标准，不如直接给例子，让我比、让我挑，再一起看差在哪，这样我更容易把脑子里的感觉说出来。

我一般觉得打字比说话容易，因为字可以随时删、改、重排。说话多半是当场交流、讨论，没法反复改。不过这也只是相对的，打字也好说话也好，都会碰到「明明知道想说什么，就是不知道怎么说」的时候，有时得来回聊、改措辞，才能慢慢说准。

## 意见不合时

跟人意见不一样时，我不会固定地争或者让，要看双方的权力和责任关系，还有能不能平等地讨论。

如果对方是领导，或者双方权力和责任差得太远，而且我判断提了不同意见对方可能拿这个压我，那我一般觉得没必要争，就让了。让了不代表我认同，只是觉得在那种关系里争下去没意思。别的情况下，我更愿意通过讨论解决。

我自己是负责人、要拍板的时候，看事情急不急。不急的就跟大家好好商量，尽量商量出共识；特别急的，等不到所有人都同意，我就先听一圈意见，再自己拍板。

拍错了就改。我还会复盘一次，把当时什么情况、为什么那么定记下来。错要改，当时为什么那么决定也得留着，以后回头看才看得懂，光说一句「当初判断错了」没什么用。

别人的失误影响到我负责的事，我第一反应一般是无语。接下来怎么办看情况。比如漫协那次，线上组组长一直不传迎新晚会录播，我就自己接过来了（见 [whudays.md](experience/whudays.md)）。别的时候我也许什么都做不了，那就只能无语一下。我没有一套固定的处理办法。

碰到不合理、我又没权限改的规则或流程，我的做法很简单：能绕就绕，绕不了就躺平。我不一定认同，可改不了，也不值得花力气去争、去推，那就不折腾了。

## 帮人的边界

有人来问技术、求职这类问题，我一般乐意帮。不过也看对方是从哪儿找到我的，跟我说话是什么态度。

这个「态度」我还说不太清楚。客不客气、问题写得规不规范算一部分，但我在意的还不止这些。我碰到过一些人，说话完全只顾自己，根本不管对面是谁，跟这种人聊天很难受，也会影响我还想不想帮。到底哪些行为算这一类，我还没总结出完整的规矩。
